# API Documentation and Postman Collection

This document provides an overview of the API endpoints, required user roles, sample data, and a Postman collection for testing.

## 1. User Roles and Sample Credentials

The application defines the following user roles with a hierarchical structure:

*   **Admin**: Full access to all features.
*   **BrandOwner**: Manages Managers and their assigned Branch Owners. Can view and manage data for their hierarchy.
*   **Manager**: Manages Branch Owners assigned to them. Can view data for their assigned Branch Owners.
*   **BranchOwner**: Manages their own branch's sales, expenses, and stock requests.

**Sample User Credentials (generated by `server/sampleData.js`):**

## 2. API Endpoints

All API endpoints are prefixed with `/api`. The base URL for the API is assumed to be `http://localhost:5000`.

### 2.1. Authentication Endpoints (`/api/auth`)

*   **Register User**
    *   **Method:** `POST`
    *   **URL:** `/api/auth/register`
    *   **Description:** Registers a new user.
    *   **Required Roles:** Public
    *   **Sample Request Body:**
        ```json
        {
            "name": "New User",
            "email": "newuser@example.com",
            "password": "password123",
            "role": "BranchOwner",
            "assignedManager": "60d5ec49f8c7a7001c8e4d1a" // Optional, if role is BranchOwner
        }
        ```
    *   **Sample Response:**
        ```json
        {
            "_id": "60d5ec49f8c7a7001c8e4d1b",
            "name": "New User",
            "email": "newuser@example.com",
            "role": "BranchOwner",
            "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
        }
        ```

*   **Login User**
    *   **Method:** `POST`
    *   **URL:** `/api/auth/login`
    *   **Description:** Authenticates a user and returns a JWT token.
    *   **Required Roles:** Public
    *   **Sample Request Body:**
        ```json
        {
            "email": "admin@example.com",
            "password": "password123"
        }
        ```
    *   **Sample Response:**
        ```json
        {
            "_id": "60d5ec49f8c7a7001c8e4d1c",
            "name": "Admin User",
            "email": "admin@example.com",
            "role": "Admin",
            "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
        }
        ```

*   **Get User Profile**
    *   **Method:** `GET`
    *   **URL:** `/api/auth/me`
    *   **Description:** Retrieves the profile of the authenticated user.
    *   **Required Roles:** Authenticated User
    *   **Sample Request (Headers):**
        ```
        Authorization: Bearer <JWT_TOKEN>
        ```
    *   **Sample Response:**
        ```json
        {
            "_id": "60d5ec49f8c7a7001c8e4d1c",
            "name": "Admin User",
            "email": "admin@example.com",
            "role": "Admin",
            "createdAt": "2023-01-01T12:00:00.000Z",
            "updatedAt": "2023-01-01T12:00:00.000Z"
        }
        ```

*   **Update User**
    *   **Method:** `PUT`
    *   **URL:** `/api/users/:id`
    *   **Description:** Updates an existing user's details.
    *   **Required Roles:** Admin
    *   **Sample Request Body:**
        ```json
        {
            "name": "Updated Brand Owner",
        ```


*   **Delete User**
    *   **Method:** `DELETE`
    *   **URL:** `/api/users/:id`

        ```
        Authorization: Bearer <ADMIN_JWT_TOKEN>
        ```
    *   **Sample Response:**
        ```json
        {
            "message": "User removed"
        }
        ```

*   **Get Users by Role**
    *   **Method:** `GET`
    *   **URL:** `/api/users/role/:role`
    *   **Description:** Retrieves users filtered by their role.
    *   **Required Roles:** Admin, BrandOwner
    *   **Path Parameters:** `role` (e.g., `Manager`, `BranchOwner`)
    *   **Sample Request (Headers):**
        ```
        Authorization: Bearer <BRANDOWNER_JWT_TOKEN>
        ```
    *   **Sample URL:** `/api/users/role/Manager`
    *   **Sample Response:**
        ```json
        [
            {
                "_id": "60d5ec49f8c7a7001c8e4d1e",
                "name": "Manager One",
                "email": "manager1@example.com",
                "role": "Manager",
                "assignedManager": "60d5ec49f8c7a7001c8e4d1d"
            }
        ]
        ```

*   **Assign User**
    *   **Method:** `PUT`
    *   **URL:** `/api/users/:id/assign`
    *   **Description:** Assigns a manager to a user (e.g., BrandOwner assigns Manager, Manager assigns BranchOwner).
    *   **Required Roles:** Admin, BrandOwner
    *   **Path Parameters:** `id` (ID of the user to be assigned)
    *   **Sample Request Body (Admin assigning a manager to a BranchOwner):**
        ```json
        {
            "assignedManager": "60d5ec49f8c7a7001c8e4d1e" // ID of the Manager
        }
        ```
    *   **Sample Response:**
        ```json
        {
            "message": "User assigned successfully",
            "user": {
                "_id": "60d5ec49f8c7a7001c8e4d1f",
                "name": "Branch Owner A",
                "email": "branchownerA@example.com",
                "role": "BranchOwner",
                "assignedManager": "60d5ec49f8c7a7001c8e4d1e"
            }
        }
        ```

*   **Get User Hierarchy**
    *   **Method:** `GET`
    *   **URL:** `/api/users/hierarchy`
    *   **Description:** Retrieves the user hierarchy based on the authenticated user's role.
    *   **Required Roles:** Admin, BrandOwner, Manager
    *   **Sample Request (Headers):**
        ```
        Authorization: Bearer <BRANDOWNER_JWT_TOKEN>
        ```
    *   **Sample Response (for BrandOwner):**
        ```json
        [
            {
                "_id": "60d5ec49f8c7a7001c8e4d1e",
                "name": "Manager One",
                "email": "manager1@example.com",
                "branchOwners": [
                    {
                        "_id": "60d5ec49f8c7a7001c8e4d1f",
                        "name": "Branch Owner A",
                        "email": "branchownerA@example.com"
                    }
                ]
            }
        ]
        ```

### 2.8. Export Endpoints (`/api/export`)

*   **Export Sales to Excel**
    *   **Method:** `GET`
    *   **URL:** `/api/export/sales/excel`
    *   **Description:** Exports sales data to an Excel file.
    *   **Required Roles:** Admin, BrandOwner, Manager, BranchOwner
    *   **Query Parameters:** Same as `Get Sales Report`
    *   **Sample URL:** `/api/export/sales/excel?type=monthly`
    *   **Response:** Downloads an `.xlsx` file.

*   **Export Expenses to Excel**
    *   **Method:** `GET`
    *   **URL:** `/api/export/expenses/excel`
    *   **Description:** Exports expenses data to an Excel file.
    *   **Required Roles:** Admin, BrandOwner, Manager, BranchOwner
    *   **Query Parameters:** Same as `Get Expense Report`
    *   **Sample URL:** `/api/export/expenses/excel?type=daily`
    *   **Response:** Downloads an `.xlsx` file.

*   **Export Sales to PDF**
    *   **Method:** `GET`
    *   **URL:** `/api/export/sales/pdf`
    *   **Description:** Exports sales data to a PDF file.
    *   **Required Roles:** Admin, BrandOwner, Manager, BranchOwner
    *   **Query Parameters:** Same as `Get Sales Report`
    *   **Sample URL:** `/api/export/sales/pdf?type=all`
    *   **Response:** Downloads a `.pdf` file.

*   **Export to CSV**
    *   **Method:** `GET`
    *   **URL:** `/api/export/:type/csv`
    *   **Description:** Exports data (sales or expenses) to a CSV file.
    *   **Required Roles:** Admin, BrandOwner, Manager, BranchOwner
    *   **Path Parameters:** `type` (sales, expenses)
    *   **Query Parameters:** Same as `Get Sales Report` or `Get Expense Report` depending on `type`.
    *   **Sample URL (Export Sales to CSV):** `/api/export/sales/csv?type=weekly`
    *   **Response:** Downloads a `.csv` file.

## 4. Steps for Setting Up and Testing with Postman

To effectively test the API using the provided Postman collection, follow these steps:

1.  **Start the Backend Server:**
    *   Navigate to the `server` directory in your terminal.
    *   Install dependencies if you haven't already: `npm install`
    *   Start the server: `npm start` (or `node server.js` if `npm start` is not configured).
    *   Ensure your MongoDB is running and accessible.

2.  **Seed the Database with Sample Data:**
    *   Open a new terminal in the `server` directory.
    *   Run the seeder script to populate the database with sample users, sales, expenses, stock requests, and transport data:
        ```bash
        node seeder.js
        ```
    *   This will clear existing data and create new sample data, including users with different roles and their hierarchical assignments.

3.  **Import the Postman Collection:**
    *   Open Postman.
    *   Click on `File > Import` (or the `Import` button in the workspace).
    *   Select the `Postman_Collection.json` file that was generated.
    *   The collection named "Inventory Management API" will be imported into your Postman workspace.

4.  **Set Up Environment Variables:**
    *   In Postman, select the "Inventory Management API" collection.
    *   Go to the "Variables" tab for the collection.
    *   Ensure the `BASE_URL` variable is set to `http://localhost:5000` (or your server's address if different).
    *   The collection includes pre-request scripts for login requests that automatically set `JWT_TOKEN` and user ID variables (e.g., `ADMIN_JWT_TOKEN`, `ADMIN_ID`, `BRANDOWNER1_JWT_TOKEN`, etc.) after a successful login.

5.  **Execute Login Requests First:**
    *   Before testing other endpoints, run the login requests for each role (e.g., "Login Admin", "Login Brand Owner 1", "Login Manager 1", "Login Branch Owner A") within the "Authentication" folder.
    *   This will populate the environment variables with the necessary JWT tokens and user IDs, which are used in subsequent requests for authorization and dynamic URL paths.

6.  **Test Endpoints:**
    *   Once the JWT tokens and user IDs are set, you can proceed to test other endpoints.
    *   **Important:** For requests that require specific IDs (e.g., `GET /api/users/:id`, `PUT /api/expenses/:id`), you will need to replace the placeholder IDs (e.g., `{{BRANCHOWNERA_ID}}`, `{{EXPENSE_ID}}`) with actual IDs obtained from previous successful `GET` or `POST` requests. For example, after creating an expense, the response will contain its `_id`, which you can then use to update or delete it.
    *   Pay attention to the "Required Roles" specified in the documentation for each endpoint to ensure you are using the correct JWT token for authorization.

By following these steps, you can effectively test all the API endpoints and verify their functionality with different user roles and sample data.
